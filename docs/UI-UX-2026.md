# Games Atlas · UI/UX 深度优化与验收规范

> **设计版本：2026-11-09** · 代码实现：[`site/`](../site/) · 核心目标：**尽量缩短“找到适合自己的项目并判断可信度”的路径**。

## 设计要解决的问题

旧首页是普通分类卡片目录，状态仅在一行低对比度的小字中展示，访客很难区分“能直接在浏览器玩”“要在本地运行”和“仅用于研究的强化学习环境”。当已验证条目增加时，卡片的单一整卡跳转也让用户无法直接访问 CI 证据。

新的用户路径：**发现 → 通过过滤器确认运行方式 → 阅读证据等级 → 进入原仓库或原始 CI → 决定体验或复现**。不制作假按钮，不将 CI 当生产验收。

## 核心 UI 变化

| 设计维度 | 本轮实现 | 为什么有用 |
|---|---|---|
| 信息架构 | 首屏价值主张 → 信任边界 → 多维检索 → 项目卡 → 路线图 | 先说明能获得什么，再呈现可信的搜索结果 |
| 视觉系统 | 深色编辑式背景、青绿色高对比主操作、暖色装饰、模块化栅格与统一圆角 | 保留游戏主题，同时建立统一的视觉层级 |
| 交互筛选 | 项目文本、七类分类、桌面/浏览器候选/本地 Web/环境/AI 等运行形态、CI 结果和排序 | 防止“所有项目都可直接玩”的误解 |
| 状态表达 | 自动测试通过 / 浏览器测试通过 / 构建通过 / CI 失败 / 未验证；另行提示部署阻塞 | 用事实区别运行范围和生产体验 |
| 信任行动 | 一张项目卡有单独的“原仓库”和“验证记录”链接 | 可直接追溯原始 GitHub 证据；不存在嵌套链接 |
| 包容性 | 键盘 `/` 直达搜索、Skip link、焦点可见、表单标签、状态计数播报、减少动画 | 鼠标、触控及键盘用户均可完成发现任务 |
| 响应式 | 3/2/1 列卡片栅格、表单 4/2 列、移动端简化导航 | 优先保障窄屏检索与阅读 |
| 主题 | 深浅色切换，在本地浏览器保存选择 | 在不同光线与阅读环境保持舒适 |

### 设计 Token

- 主要深色背景：`#0b1221`；表面：`#111b2c`；文本：`#f5f7fc`；次级：`#aebbd0`。
- 主强调：`#9af0cb`，优先用于“探索”、可访问的证据链接、焦点和导航。
- 浅色主题由 CSS 自定义属性覆盖；不从外部加载字体、图片、追踪脚本或 JS 框架。
- 断点：`1000px`（双列结果）、`760px`（单列首屏与二列表单）、`520px`（单列结果和移动端导航）。
- `prefers-reduced-motion: reduce` 禁用过渡与运动效果。

## 硬性事实与安全约束

- 数据只来自 `data/games.json`、`data/phase1.json`、`data/phase2.json`、`data/phase3.json` 的**公开白名单字段**；未收录的项目默认显示“尚未进入运行验证批次”。
- 前端使用 `textContent` 设置名称、简介和状态，避免来自项目数据的 HTML 注入。
- 对外跳转必须为 `https://github.com/1998x-stack/` 前缀，并附 `target=_blank rel=noopener noreferrer`。
- “浏览器候选”不是“已在线可玩”；“自动测试通过”不是“真实物理设备验收”。
- 阶段数据缺失时页面仍能显示 35 条公开目录，不提升任何状态为已验证。

## 独立的自动化验收

在 `main` 推送及 PR 触发 `Validate catalog`：

1. 35 项目录和 35 项 P1/P2/P3 唯一跟踪状态完整加载。
2. 搜索、类别快捷筛选、运行形态、状态过滤、排序与重置能正确组合。
3. 正确显示 25 项具有成功测试/构建或历史 CI 证据、1 项历史 CI 失败，避免伪造“已在线玩”。
4. 35 条仓库链接和 27 条原始工作流证据链接独立、安全。
5. 390px 移动端无横向溢出、主题切换与页面刷新后保留主题。
6. 1440px 桌面端展示语义化主结构、唯一一级标题和完整分类控件。
7. `screenshots/mobile-390.png` 与 `screenshots/desktop-1440.png` 自动存入 Actions **games-atlas-ui-evidence** 工件。

**验证范围界限：** Playwright Chromium 的截图和 DOM 测试是技术检查；配色可读性、版面节奏、真实触控设备以及正式公网的人工体验仍建议人工复核，不能仅凭一次截图冒称完全无障碍合规。

## P3 信息架构补充（2026-11-09）

第三批把游戏创作工具（`creation-tool`）、RL/基准环境（`environment`）、教程资料（`resource`）单独作为运行形态，不再把这些项目当成浏览器可玩游戏。状态增加 **仅安全契约通过**、**仅算法组件通过**、**历史 CI 通过** 三种证据范围；对于需服务端、平台/ROM 受限或历史依赖项目，卡片额外展示限制。P1/P2/P3 总共 **35 项状态登记**，其测试成功/失败/待验统计分别为 **25 / 1 / 9**。新浏览器回归测试包含第三批筛选与状态清单完整性，并验证 P3 manifest 不可用时不会出现虚假的可玩声明。


**第三批最新证据说明：** microRTS 以实际 Java 引擎完成一次 205 周期有胜负对局；AI-Game-Generator 在 Chromium 测试中证明 srcdoc 无法访问父页面 DOM/localStorage 并拒绝伪造消息。这些结果属于各自的运行/安全边界，不等价于生产网站正式验收或全应用渗透测试。

新证据标签将 **CPU 固定种子对照** 与 **打包器文件隔离** 分开显示：前者是模型规划小实验，不代表完整神经网络训练；后者是输入文件边界回归，不是整个服务的安全认证。缺少真实运行证据的项目仍不能显示“已在线可玩”。

**P3 策略训练标签：** `training-ci` 只代表有固定种子、参数更新、留出测试和多种子原始记录的 NumPy 线性 Actor-Critic。它与只进行规划对照的 `experiment-ci` 不同，但都不是“网页已可玩”，也不意味着原 PyTorch 深度模型训练全部复现。

**同环境算法对照（P3）：** 新的 `comparison-ci` 标签对应同种子、同回合数的 PyTorch 神经网络与 NumPy 线性 Actor-Critic 实验，并直接链接 GitHub Actions 原始 JSON；其证据限于现代教学实现，不代表历史 Notebook 已完成复现或可在线试玩。项目的成功证据**项目数仍为 25/35**，因为这只是 RL-Adventure-2 的额外验证，不新增项目。

**P3 原 Notebook 风格 n-step A2C：** `vector-a2c-ci` 代表使用相同 16 环境/5 步算法结构并达到原 20,000 向量步预算的现代 CPU 测试，但并不表示原多进程源码逐行通过；不能把不同训练交互预算的三种算法绘成公平排行榜。成功 CI 的顶层项目数仍为 **25/35**，此次新增的是单个项目的更强证据。
